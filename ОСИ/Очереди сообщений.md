#оси 
Реализация очередей сообщений (в Windows и называют "каналами сообщений") такая же, как реализация файлов. В оперативной памяти ведется таблица, которая со всеми очередями сообщений системы

Посмотреть таблицу можно при помощи утилиты `ipcs -q`

Каждая запись в таблице отражает определенную очередь сообщений. 

### Поля таблицы
- имя - целочисленный идентификатор (ключ), присвоенный очередью, которая его создала (`key_t key;`);
- идентификатор владельца - число;
- идентификатор назначенного владельца (может быть только один, фиксируется последнее назначение). Может совпадать с идентификатором владельца;
- идентификатор группы;
- идентификатор назначенной группы - то же самое, что с владельцами;
- права доступа
Все эти параметры объединены в структуру `struct ipc_perm`. Эта структура описана в заголовочнике `<sys/ipc.h>`

Есть еще поля в таблице, но которые не содержатся в структуре ipc_perm:
- msg_first - указатель на первое сообщение в очереди
- msg_last - указатель на крайнее сообщение в очереди
- msg_cbytes - общее количество байтов во всех сообщениях очереди
- msg_qnum - максимальное количество сообщений в очереди на данный момент
- msg_qbytes - максимальное количество байтов всех сообщений в очереди 
- msg_lspid - идентификатор процесса, который последним записал сообщение в очередь
- msg_lrpid - идентификатор процесса, который последним прочитал сообщение из очереди
- msg_stime - время записи последнего сообщения в очередь (в секундах, от 1 января 1970)
- msg_rtime - время чтения последнего сообщения из очереди
- msg_ctime - время последнего изменения управляющих параметров очереди (первые 6 полей)

Все-все поля таблицы можно найти в структуре `struct msqid_ds`. Этот тип данных описан в `<sys/msg.h>`

Каждое сообщение - структура данных типа `struct msg`. Он тоже определен в `<sys/msg.h>` и  имеет поля:
- msg_type - тип сообщения (целое число). При создании тип сообщения $\geq 0$
- msg_ts - количество байтов 
- msg_spot - указатель на текст сообщения
- msg_next - указатель на следующее сообщение в очереди или нулевой указатель

### Связанные системные вызовы
- msgget(name) - открывает или создает очередь сообщений с именем name
- msgsnd() - записать сообщение в очередь
- msgrcv() - прочитать сообщение из очереди
- msgctl(name) - удаляет очередь с именем name

Для работы нужны заголовочники:
```
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/msg.h>
```

Примеры работы вызовов:
- `int msgget(key_t key, int flag);` Здесь key - имя очереди, flag - фиксатор. Если 0 - открываем, иначе - создаем с указанными правами (IPC_CREAT|0664). Возвращает пользовательский дескриптор открытого файла
- `msgget(s, 0) = -1` - если очередь не создана или нет прав на чтение
- `msgget(s, IPC_CREAT|0640)` - создаем новую очередь
- `msgget(s, IPC_CREAT|0640) = -1` - если очередь есть и мы не являемся ее владельцем
- `ftok()` - вернет число, которое не занято (в контексте имени очереди)
- `int msgsnd(int fd, const void* buf, int len, int flag)`:
	- int fd - номер пользовательского дескриптора (то же, что возвращает msgget)
	- void* buf - указатель на объект, который содержит сообщение (`struct msgbuf { long mtype; char text[MSGMAX];}`) - тип и текст
	- int len - размер в байта поля текста сообщений
	- int flag - IPC_NOWAIT (не блок)
Возвращает 0 при успехе и -1 при ошибке (если стоит флаг IPC_NOWAIT)
